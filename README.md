# mock-services — тестовые моки банков и касс по официальным протоколам

Опенсорс-проект: сервис, имитирующий **банк-эквайринг** и **облачную кассу/ОФД**
по их официальным протоколам, чтобы любой участник рынка тестировал свою
платёжную и фискальную интеграцию **до договора с провайдером** — с честными
схемами, кодами ошибок, сценариями отказов и внятными подсказками.

> Статус: **стартовый пакет** (документы и референсы; код адаптеров
> переносится из Lovii отдельно). Спека: [`docs/canon/MOCK_SERVICES_SPEC.md`](docs/canon/MOCK_SERVICES_SPEC.md)

## Зачем

1. Тестовые контуры банков/ОФД доступны только после договора — мок даёт
   рабочий протокол сразу.
2. Реальные шлюзы возвращают сухие коды — мок объясняет ошибку, указывает
   поле, даёт рекомендацию и ссылку на пункт документации.
3. Сценарии отказов (недостаток средств, таймаут, дубль вебхука, чарджбэк,
   отказ ККТ) — переключателем, а не «ждём боевой инцидент».
4. Новые провайдеры добавляются адаптером-декларацией, без форка сервиса.

## Быстрый старт

```bash
npm test            # selftest обоих сервисов (zero npm dependencies, Node >= 18)
docker compose up   # стенд «банк + касса»: tbank-mock :3100, kassa-mock :3101
```

Контракты и переменные окружения — в README каждого сервиса
(`services/tbank-mock`, `services/kassa-mock`).

## Происхождение

Семя проекта — боевые моки платформы Lovii (lovii-tech): `tbank-mock`
и `kassa-mock`, проверенные на staging-стенде (selftest 13/13 у кассы).
Lovii остаётся первым потребителем; его внутренние моки живут в `lovii-core`,
пока сервис не созреет до самостоятельного деплоя.
