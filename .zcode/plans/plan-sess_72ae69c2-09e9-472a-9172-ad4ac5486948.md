## Цель
Чистим публичные артефакты mock-services от внутренней ИС, выпускаем релиз v0.7.0 с урезанным рантайм-образом, удаляем старый релиз v0.6.0 и готовим **самостоятельный самодостаточный деплой-артефакт** для стейджинга (Т-Банк + Ferma). `lovii-core` не трогаем: lovii интегрируется с мок-контуром как любой внешний потребитель — по документации, через URL/`TBANK_API_URL`/`FERMA_API_URL`.

## Фаза 1 — убрать внутренние доки из git (вперёд, история не трогается)

Локально сохраняем копии в `~/LOVII/lovii_docs/mock-services-internal/` (вне репозитория), затем `git rm -r`:

- `docs/audit/` (18 внутренних AI-аудитов, 1.3M)
- `docs/briefs/` (брифы для агентов)
- `docs/canon/` (внутренние спеки)
- `docs/reference/` (конспекты документации провайдеров — главный ИС-риск)
- `docs/rfc/` — **оставляем** (публичная дизайн-спека RFC-001, на неё ссылаются `SECURITY.md` и хинты в `server.js`)

Сопутствующие правки:
- `package.json`: убрать `test:upstream`/`check:upstream` из `npm test`; удалить `scripts/sync-upstream*.js` и workflow `sync-upstream.yml` (их предмет — сверка снапшотов чужой документации).
- `scripts/check-protocol-drift.js`: проверить чтения (по разведке — только `docs/openapi/*` + `docs/integration/atol.md`, которые остаются), поправить при необходимости.
- `README.md`, `CONTRIBUTING.md`, `AGENTS.md`, `SECURITY.md`, `services/*/README.md`: убрать битые ссылки (находим прогоном `npm run check:links` + grep). В `AGENTS.md` пометить, что внутренние доки перенесены в `lovii_docs` вне репозитория.
- `.github/workflows/ci.yml`: убрать шаги `check:upstream`/`test:upstream`.

Прогон: `npm test`, `check:links`, `check:drift`. Ветка `docs/strip-internal-ip` → PR в `main`.

## Фаза 2 — рантайм-образ без dev-скриптов

`Dockerfile`: `COPY scripts ./scripts` → `COPY scripts/docker-healthcheck.js ./scripts/docker-healthcheck.js`. Selftest'ы, `protocols/`, `docs/integration`, `docs/openapi` остаются — CI-джоба `docker` (selftests внутри образа) не ломается.

Прогон: `npm run test:compose`, `node scripts/docker-smoke.js`, `npm test`. Ветка `chore/runtime-image-slim` → PR.

## Фаза 3 — самодостаточный стейджинг-артефакт (в mock-services, lovii-core не трогаем)

Новый файл `docker-compose.staging.yml` (+ секция в `docs/integration/` или корневой README):
- два сервиса: `tbank-mock` (:3100, `node services/tbank-mock/server.js`, `/health`) и `kassa-mock` (:3101, `node services/kassa-mock/server.js`, `/healthz`);
- `image: ghcr.io/rucorp/mock-services@sha256:<digest>` — жёсткий пин, без `build:`;
- volume на `/data`, env по умолчанию как в `docker-compose.include.yml` (safe defaults, `MOCK_HOSTED` выключен);
- доменная настройка (`MOCK_PUBLIC_BASE_URL`) — через переменные с примерами `mock-pay-staging.lovii.ru` / `mock-kassa-staging.lovii.ru` (значения — за пользователем при деплое);
- запуск одной командой: `curl -o compose… && docker compose up -d` — без клонирования репозитория.
- документация: «как задеплоить стенд» + «как подключить приложение» (указать `TBANK_API_URL`/`FERMA_API_URL` на стенд) — потребительская точка зрения, без упоминания lovii-core.

Прогон: `docker compose -f docker-compose.staging.yml config`, локальный подъём и smoke (`/health`, `/healthz`, создание платежа tbank + токен ferma), `npm run test:compose`. Ветка `feat/staging-compose` → PR.

## Фаза 4 — релиз v0.7.0 и снос v0.6.0

1. После мержа PR: PR `release: v0.7.0` — `package.json` version → 0.7.0, CHANGELOG (Unreleased → 0.7.0, включая строку о staging-compose).
2. Тег `v0.7.0` на `main` → CI `publish-ghcr` публикует образ `0.7.0`/`latest`/`sha-*`.
3. `docker pull ghcr.io/rucorp/mock-services:0.7.0`, взять digest.
4. PR: пин `MOCK_IMAGE_DIGEST` в `docker-compose.include.yml` и digest в новом `docker-compose.staging.yml` → новый digest.
5. Удалить релиз `v0.6.0` (`gh release delete`) и тег `v0.6.0` (`git push origin --delete v0.6.0`); почистить старые версии GHCR-пакета (`0.6.0`, `sha-*`). Историю git не трогаем.

## Порядок и проверки
- Каждая фаза — отдельный PR (правила AGENTS.md), `npm test` до и после.
- Итоговый отчёт: что удалено, digest нового образа, выводы прогонов; отдельно отмечу: **история git всё ещё содержит удалённые доки** (публично в старых коммитах) — при желании отдельная задача по `git filter-repo`.
