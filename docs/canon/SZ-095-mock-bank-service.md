# SZ-095 — Проект «мок-банк»: опенсорс-сервис тестирования эквайринга

> Статус: **К постановке (черновик, ждёт развилок владельца)**
> Приоритет: **P2**
> Источник: владелец 08.10 — «будем создавать опенсорс проект мок банк + касса,
> чтобы тестировать свои платёжки, добавлять разные банки и кассы, давать
> корректные инструкции для интеграции и качественное тестирование»
> Спека: [`MOCK_SERVICES_SPEC.md`](../MOCK_SERVICES_SPEC.md)
> Репо: развилка §5.1–5.3 спеки (монорепо mock-services vs отдельные)
> Дата постановки: 2026-10-08

## Что решить / сделать

1. Вынести `tbank-mock` из lovii-core (staging-extras, :3100) в
   самостоятельный сервис по архитектуре спеки §2: ядро (транзакции,
   машина состояний, вебхуки, идемпотентность) + адаптер «Т-Банк
   эквайринг».
2. Довести протокол до официальной документации эквайринга Т-Банка:
   Init/Confirm/Cancel/GetState, Notification-вебхуки с подписью и
   ретраями, коды ошибок — с сверкой по доке (§6.1 спеки).
3. DX-слой для банкового адаптера: разбор ошибки (§6.2 спеки),
   сценарии отказов (успех/отказ/таймаут/дубль вебхука/отмена/чарджбэк),
   журнал вебхуков в панели.
4. Selftest-набор + README «интеграция за 10 минут».

## Критерий приёмки

- Lovii (core, e2e, симулятор выплат T-013) гоняется против сервиса без
  правок кода — совместимость с текущим `tbank-mock` сохранена.
- Все сценарии отказов воспроизводятся переключателем, вебхуки
  идемпотентны, selftest 🟢.
- Ошибки интеграции возвращают код+объяснение+рекомендацию+ссылку на доку.

## Развилки (спека §5)

Репо/имя (5.1), лицензия (5.2), стек (5.3), публичность кода (5.4) —
решить владельцем до старта реализации.

## Запретные зоны

Не трогать боевой платёжный контур Lovii (`config/payments.php`,
платёжные домены/экшены) — задача про внешний сервис; переключение Lovii
на новый сервис — отдельная задача-миграция.
