## Канон (уже зафиксирован)

- Юридическая модель: Правообладатель — торговый агент, чек выбивает
  Правообладатель с признаком агента и ИНН Лицензиата как Поставщика
  (`money_flow_public.md` §2.1, Оферта присоединения §12.2.3, Публичная
  оферта §2.6).
- Механика двухчековая: «Предоплата 100%» на поступление оплаты, «Полный
  расчёт» на подтверждение/передачу; чек возврата при отмене.
- Данные: `fiscal_documents` — DATA_MODEL §2.9; пороги/ретраи — PARAMS §11;
  API — API_SPEC §3.14.

## Что реализовать (Фазы 3–4 плана)

1. core: миграция `fiscal_documents`, `FiscalDocumentManager`,
   провайдер-интерфейс + `FermaProvider` (и `MockProvider` для стенда),
   триггеры: payment confirmed → prepayment; передача заказа → full_payment;
   отмена/возврат/чарджбэк → refund; очередь + ретраи + internal callback
   `/api/internal/v1/fiscal/callback`.
2. admin: реестр фискальных документов + ручной перезапуск упавших
   (высокий доступ, audit-log).
3. b2b: раздел «Чеки» по заказам своих точек — база месячного отчёта
   Лицензиату (к 5-му числу, Оферта присоединения §6.4.2).
4. app: квитанция — статус «чек сформирован» + ФД/ФП/ссылка.
5. Приёмка (Фаза 4): мок → тестовый контур Ferma → бой 1₽: чек №1 → сверка
   ФД/ФП (кабинет + «Проверка чеков ФНС») → чек №2 → возврат → негатив
   (ретраи/алерты) → инвариант леджера Σ=0. Каждая боевая операция — по
   явному «го» владельца.

## Развилки владельца (НЕ решать агенту)

1. **Момент «Полного расчёта»**: на статусе `ready` или `completed`; для
   доставки и самовывоза момент может различаться. Дефолт спеки: на передаче
   (`ready`) — утвердить или поменять.
2. **Кэшбэк баллами в чеке**: `Payments.Provision` («иная форма оплаты») vs
   уменьшение суммы электронного платежа. Дефолт спеки: Provision.
3. **Вердикт юриста по реквизитам** (блокер только финальных значений, не
   кода — поля конфигурируемые): AgentSign (какой тип агента), СНО
   (УСН «доходы»?), предмет расчёта (`commodity` vs `service` с агентским
   признаком).
