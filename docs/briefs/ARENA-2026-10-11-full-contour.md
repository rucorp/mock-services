# Бриф арены: полный контур тестовых сервисов (банки топ-5 + кассы/ОФД)

> Дата: 2026-10-11 · Постановка: владелец · База: `main` @ `6a7cdfe` · Репо публичный
> Предыдущий бриф ([ARENA-2026-10-11-external-service-and-enrichment.md]) остаётся в силе
> в части Lovii-интеграции (issue #2), но приоритет смещается на THIS бриф.

## 0. Цель в одном абзаце

Превратить mock-services в **полный контур тестовых сервисов для интеграторов**:
любой разработчик должен уметь тестировать свои платёжные и фискальные
интеграции так же, как на реальных тестовых стендах провайдеров — по официальным
протоколам, с честными кодами ошибок, сценариями отказов и подсказками. Для
этого: (1) ресёрч официальной документации банков РФ топ-5 и облачных
касс/ОФД-провайдеров, (2) адаптеры по существующему паттерну
(`packages/core` + один файл на сервис + selftest + integration-гайд),
(3) копирайт-шапки и атрибуция по стандарту.

## 1. Ресёрч (первый этап, результат — в docs/reference/)

Найти и законспектировать официальную публичную документацию:

**Банки/эквайринг (РФ топ-5):** Сбербанк (sbi.sberbank / эквайринг REST),
Альфа-Банк (Альфа-Эквайринг), ВТБ (эквайринг), Т-Банк (уже есть — сверить с
developer.tbank.ru), ЮKassa или Robokassa (агрегаторы, по выбору — у них
открытее всего доки). Для каждого: auth, Init/платёж/статус/отмена/возврат,
вебхуки и подпись, тестовые карты/стенды, ссылки на разделы доки.

**Кассы/ОФД:** АТОЛ Онлайн (уже в роадмапе этапа 9), Первый ОФД, Такском
(ФН-оператор), Контур.ОФД, OFD Ferma (уже есть — сверить). Формат тот же:
auth, чек/возврат, статусы/колбэки, тестовый контур.

Формат конспекта — как существующие `docs/reference/tbank/01-…06-*`:
по файлу на тему, ссылки на первоисточник, отличия от уже реализованных
адаптеров. Конспект = «достаточно, чтобы написать адаптер, не открывая сайт».

## 2. Адаптеры (второй этап)

Порядок: **сначала один банк ресёрчем глубже остальных** (рекомендуем ЮKassa
или Сбербанк — самые открытые доки) до готового адаптера, дальше — по одному.
Каждый адаптер обязан повторить паттерн существующих:

- один файл `services/<bank>-mock/server.js`, zero-dependency, Node ≥ 18;
- ядро `packages/core` (store/вебхуки/каталог ошибок/журнал) — без дублирования;
- честные коды ошибок провайдера + DX-слой (подсказка + ссылка на раздел доки);
- сценарии отказов (fail-/hang-/таймаут/дубль вебхука) по образцу tbank/kassa;
- selftest (`services/<bank>-mock/selftest.js`) + строка в `npm test`;
- `docs/integration/<provider>.md` — «интеграция за 10 минут»;
- сервис в корневом `docker-compose.yml` с healthcheck.

Публичные имена провайдеров в названиях сервисов — с оговоркой о совместимости
(как в NOTICE: товарные знаки принадлежат владельцам, использованы для
обозначения совместимости).

## 3. Копирайт и атрибуция (обязательный слой, стандарт владельца)

Применять к **каждому созданному/редактируемому файлу** (не массовый обход —
только новые и тронутые файлы, «правило бойскаута»):

- Код (`.js`, `.yml`, `.sh`): шапка в начале файла
  `© 2026 ООО «Аксиома» ИНН:7842223709 · mock-services · Apache-2.0` +
  `SPDX-License-Identifier: Apache-2.0`.
- Документы (`.md`): `© 2026 ООО «Аксиома» ИНН:7842223709 ·
  https://github.com/rucorp/mock-services · все права защищены` +
  строка `Документ проекта mock-services (оригинал: rucorp/mock-services).`
- Подвалы запрещены. Stop-лист: `.json`, сгенерированные файлы, бинарники.
- Всякий пользователь/форк обязан сохранять NOTICE и ссылку на оригинал —
  см. NOTICE (уже обновлён).

## 4. Ограничения и критерии приёмки

- Не ломать существующее: `npm test` зелёный до и после; tbank-mock и
  kassa-mock — эталон, их контракт не менять.
- Провайдеро-нейтральность: lovii-профили только через env, дефолты не знают
  про Lovii.
- Каждый адаптер = PR с зелёным CI; в отчёте PR — что покрыто, что нет,
  ссылки на разделы официальных док.
- Если официальная дока провайдера закрыта/требует договора — честно отметить
  в конспекте и строить адаптер по publicly-известной части; не выдумывать
  несуществующие поля.

## 5. Порядок работы

1. Ресёрч-отчёт (§1) → PR в `docs/reference/` → владелец подтверждает выбор
   банков/касс первой волны.
2. Адаптеры по одному (§2), каждый — отдельный PR.
3. Копирайт-слой (§3) соблюдается во всех PR автоматически.
