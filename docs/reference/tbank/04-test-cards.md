# Конспект: тестовые карты Т-Банка

Источники: `docs/oplata_multisplit.pdf` §7, `docs/vyplaty-multisplit.pdf` §9. Срок действия
и CVV тестовых карт — любые (в доках фигурируют `12/25` и `123`). Тестовые карты работают
на тестовой среде.

## Оплата: 3-D Secure 2.0

| PAN | Поведение |
|---|---|
| `2201382000000013` | успех, Frictionless Flow (`AUTHENTICATION_SUCCESSFUL`) |
| `2201382000000047` | успех, Challenge Flow (`CHALLENGE_REQUIRED`) — редирект на ACS, OTP; метод Static Passcode, верный пароль `1qwezxc` |
| `2201382000000005` | отказ, эмитент отклонил аутентификацию (`ACCOUNT_VERIFICATION_REJECTED`, R) |
| `2201382000000021` | отказ оплаты / карта не поддерживает 3DS (`NOT_AUTHENTICATED`, N) |
| `2201382000000039` | успех, `ATTEMPTS_PROCESSING_PERFORMED` (A) — эмитент не поддерживает 3DS v2.1, Pay разрешён |
| `2201382000000831` | отказ — **недостаточно средств** |

## Как использовать в мок-стенде

Мок банка распознаёт сценарий по PAN (таблица выше) и ведёт себя как банк: frictionless —
сразу `AUTHORIZED`, challenge — промежуточный экран с проверкой кода, «недостаточно средств» —
`REJECTED` с соответствующим ErrorCode на FailURL. Это позволяет гонять все ветки статусной
модели без реального тестового контура.
