# Альфа-Банк — тестовый контур и карты

Срез на 2026-10-11. Источники: [официальный список тестовых карт](https://alfabank.ru/sme/payservice/internet-acquiring/docs/connection-options/api/test-cards/), [координаты и схемы взаимодействия](https://alfabank.ru/sme/payservice/internet-acquiring/docs/connection-options/api/general-description/), [REST API](https://alfabank.ru/sme/payservice/internet-acquiring/docs/connection-options/api/rest/).

## Контур

- Тестовый REST: `https://alfa.rbsuat.com/payment/rest`.
- Production обычно: `https://payment.alfabank.ru/payment/rest`; для разных учётных записей и логинов (без префикса, `r-`, `i-`) банк показывает отдельные настройки. Не фиксировать production URL до проверки merchant-координат.
- Тестовый логин/пароль и разрешения на SSL, 3DS, связки и двухстадийную оплату выдаёт банк. Страница карт предупреждает, что содержание различается по типу логина.
- Владелец карты в тесте: минимум два слова латиницей. Для 3DS ACS-пароль `12345678`. Тестовая среда не предназначена для нагрузочного тестирования.

Для проверки отказа на успешной карте ввести неверный срок/CVV либо выбрать Fail на тестовом ACS; ожидаемый шлюзовой код — `71015` («введённая информация неверна»). Срок действия и CVV из таблиц — именно тестовые данные, не реальные платёжные реквизиты.

## Для будущего адаптера

Результат регистрации (наличие `orderId`/`formUrl`) не равен финальному статусу. Проверять и тестировать отдельно: обычную оплату, холд + `deposit`, `reverse`, полный/частичный `refund`, подписанный и неподписанный callback, 3DS challenge/frictionless и отказы по `actionCode`. Не использовать тестовые креды в конфигурации мока по умолчанию.
