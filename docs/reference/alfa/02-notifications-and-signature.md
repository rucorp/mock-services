# Альфа-Банк — callback-уведомления и проверка подлинности

Первичный источник — [официальная PDF-спецификация callback](https://alfabank.servicecdn.ru/site-upload/d5/d0/4654/callback-uvedomleniya.pdf), экспортированная 11.11.2024. Инструкция по REST: [портал Альфа-Эквайринга](https://alfabank.ru/sme/payservice/internet-acquiring/docs/connection-options/api/rest/).

## Формат и события

PDF описывает callback как HTTP `GET` на URL магазина с query-параметрами. Основной набор: `mdOrder`, `orderNumber`, `operation`, `status`, `callbackCreationDate`; в зависимости от операции/настроек также `amount`, `bindingId`, `clientId`, `enabled`, `jsonParams` и др. Операции включают `approved` (холд), `deposited` (завершение/списание), `reversed`, `refunded`, `declinedByTimeout`, `declinedCardpresent`, создание/изменение связки. `status=1` — операция успешна, `status=0` — завершилась ошибкой.

Callback может быть без контрольной суммы либо с `checksum`. Документ прямо предупреждает, что неподписанное уведомление можно подделать; при обработке нужно получать актуальный статус через REST и не считать callback единственным источником истины.

## Алгоритм контрольной суммы

1. Удалить `checksum` и `sign_alias` из набора параметров.
2. Отсортировать оставшиеся имена параметров в алфавитном порядке.
3. Построить строку `name;value;name;value;...;`.
4. Сверить полученную контрольную сумму в верхнем регистре hex.

Документация описывает два режима:

- **Симметричный:** HMAC-SHA256 с общим секретным ключом.
- **Асимметричный:** проверка публичным ключом сертификата, выданного/согласованного для интеграции.

### Важная неоднозначность официального PDF

Общее описание асимметричного режима говорит о SHA-256, но приведённые Java-пример (`SHA512withRSA`) и PHP-пример (`OPENSSL_ALGO_SHA512`) используют SHA-512. Настройки могут отличаться по merchant-аккаунту и `sign_alias`. До реализации необходимо подтвердить выбранный у банка режим и алгоритм; не выбирать SHA-256 или SHA-512 по догадке. В Java/PHP-примерах контрольная сумма сравнивается как hex без учёта регистра, а алгоритм HMAC в примере — SHA-256.

## Подтверждение и повторы

После корректной обработки callback магазин должен ответить HTTP `200 OK`. Любой иной код считается неуспехом, и банк повторяет доставку до HTTP 200 либо достижения максимального количества подряд неуспешных попыток. В опубликованном PDF число попыток и интервал не указаны — не копировать параметры ретраев Т-Банка или Сбера.

Если URL обслуживается по HTTPS, PDF требует доверенный (не самоподписанный) сертификат; для RSA указана длина не менее 2048 бит и подпись не слабее SHA-256.

## Отличия от текущего мока

Т-Банк-мок присылает подписанное POST-уведомление с Token и ждёт тело `OK`; Альфа-документ описывает GET с query-параметрами и HTTP 200. Проверка Alfa должна быть отдельной реализацией. Для нового адаптера зафиксировать режим callback в конфигурации и сверять состояние заказа серверным REST-запросом.
