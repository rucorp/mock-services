# Сбер — callback и тестовый контур

Срез на 2026-10-11; относится к Ecom API из [актуальной спецификации](https://ecomtest.sberbank.ru/doc).

## Callback оплаты

- Шлюз отправляет `POST` с JSON при изменении статуса заказа на URL, заданный в настройках мерчанта; спецификация также описывает `dynamicCallbackUrl` для выбора URL в регистрации заказа.
- Базовые поля тела: `mdOrder` (UUID шлюза), `orderNumber` (номер магазина), `operation`, `status` (`1` — операция успешна, `0` — завершилась ошибкой); могут присутствовать `additionalParams`.
- Текущие `operation`: `created`, `approved` (холд), `deposited` (завершение), `reversed`, `refunded`, `declinedByTimeout`; `subscriptionCreated` относится к созданию подписки.
- Доставка: три попытки с интервалом 60 секунд. Не считать клиентский redirect или сам факт callback доказательством оплаты; сверять заказ через `getOrderStatusExtended.do`.
- В текущей публичной JSON-схеме Ecom callback нет поля подписи/`checksum`. В старом [Secure Payments callback-разделе](https://securepayments.sberbank.ru/wiki/doku.php/integration:api:callback:start) описана другая схема с подписью; её не переносить в Ecom-интеграцию без подтверждения, что у конкретного мерчанта именно этот legacy-контракт.

## Тестовый контур и карты

Тестовый REST base: `https://ecomtest.sberbank.ru/ecomm/gw/partner/api/v1/`. Тестовые `userName/password` и настройки шлюза выдаются в рамках подключения. На тестовом контуре бывают окна работ по будням (московское время): 02:00–06:00, 09:00–10:00 и 18:00–20:00; стабильность в эти интервалы не гарантируется. Контур не предназначен для нагрузочного тестирования.

Официальная таблица тестовых карт на момент среза:

Для SberPay отдельно предусмотрено мобильное Sandbox-приложение; доступ к тестовой сборке запрашивается у банка. Карты выше моделируют карточный поток, а не SberPay.

## Сопоставление с моками

`docs/reference/README-tbank-mock.md` описывает иной протокол Т-Банка, включая проверку подписи уведомления и подтверждение тела `OK`. Для нового адаптера Сбера следует воспроизвести JSON callback и банковский HTTP-200 acknowledgement; не переносить подпись Token/ретраи Т-Банка. `kassa-mock` к callback банковского платежа отношения не имеет.
