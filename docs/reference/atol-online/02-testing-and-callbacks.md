# АТОЛ Онлайн — callbacks, статусы и тестирование

Источники: [официальные тестовые реквизиты](https://atol.online/files/ffd/test_sreda.txt), [прямая интеграция и тестирование](https://help.atol.online/article/11244), [назначение тестовой кассы](https://help.atol.online/article/11254), [PDF API v4](https://atol.online/files/API_atol_online_v4.pdf), [PDF API v5 версии 3.16](https://atol.online/api_v5).

## Callback и опрос

Если передан `service.callback_url`, сервис направляет POST с результатом после завершения обработки (`done` или `fail`). В публичных руководствах, изученных к дате среза, не найдено однозначного правила для callback ACK, подписи и числа/интервалов повторов; обработчик должен быть идемпотентным. Основной механизм сверки — `GET /<group_code>/report/<uuid>`.

Рекомендация по polling в v4: максимум 3 запроса отчёта в секунду; после системной ошибки подождать не менее секунды. В протоколе v4 указано опрашивать, если callback не пришёл в течение 300 секунд. Для v5 отдельная текущая частота/срок ожидания в доступном протоколе однозначно не заданы — не переносить v4 лимит на v5 без подтверждения.

Ответ отчёта содержит `uuid`, `status` (`wait|done|fail`), `error`, `payload`; POST-ответ при принятии документа содержит UUID и состояние очереди. Сохранять оба ответа и повторно использовать `external_id` только для идемпотентного запроса того же чека.

## Практические отличия от Ferma-мока

- у ATOL direct маршруты `/possystem/v4/` и `/possystem/v5/`; текущий Ferma-мок — `/possystem/v1/`;
- ATOL принимает токен в `Token` header; текущий Ferma-контракт передаёт `token` в query;
- у ATOL дедупликация `external_id` возвращает ранее назначенный UUID; текущий Ferma-мок отвечает ошибкой на дубль;
- callback URL и polling — альтернативные каналы результата; callback нельзя считать обязательно-подписанным или повторяемым по правилу Ferma.
