# Контур.ОФД — доступ, тестовый/боевой API и авторизация

Срез публичной [документации API Контур.ОФД](https://docs-ofd-api.kontur.ru/) на 2026-10-11. Документация описывает чтение фискальных данных, не создание чеков.

## Endpoints

| Назначение | URL |
|---|---|
| Авторизация, общий для двух сред | `https://api.kontur.ru/` |
| Боевой API | `https://ofd-api.kontur.ru/` |
| Тестовый API | `https://ofd-project.kontur.ru:11002/` |

На тестовой площадке есть демо-организации и тестовые кассы с автоматически формируемыми документами. Ключ интегратора и реквизиты доступа выдаются по запросу; статические demo credentials/API key в открытой документации не приведены.

## Два обязательных уровня доступа

1. **Пользовательская сессия (`auth.sid`).** При логине/пароле отправить `POST https://api.kontur.ru/auth/authenticate-by-pass?login=<email>`; пароль передаётся текстом в UTF-8 body. Успешный ответ JSON содержит `Sid`. Для методов отправлять `Authorization: auth.sid <Sid>` (или Cookie `auth.sid=...`). Sid по умолчанию живёт 30 дней, но может быть отозван раньше; HTTP 401 / `errorCode: 401002` означает получить новую сессию.
2. **Ключ интегратора.** Каждый запрос к API данных также обязан содержать `X-Kontur-Ofd-ApiKey: <key>`. Ключ и пользовательский Sid — разные credentials; ключ интегратора приходит от Контур.ОФД.

Интегратор запрашивает тестовый/боевой доступ и способ аутентификации у Контур.ОФД. Для касс с ИНН, отличным от ИНН интегратора, владелец кассы должен дать согласие на передачу фискальных данных; для касс своего ИНН такое согласие не требуется.

## Отличие от существующего Ferma-мока

`kassa-mock` принимает чек на регистрацию и возвращает очередь печати. Контур.ОФД API, описанный здесь, предоставляет **read-only** доступ к организациям, кассам, документам и статистике. Не подменять чтение ФД вызовами `/sell` или создавать в Контуре receipt-writing API, которого нет в публичной документации.
