# Интеграция: эквайринг Т-Банка через mock (10 минут)

Мок воспроизводит контракт EACQ/Мультирасчеты по официальной документации
(https://developer.tbank.ru/eacq): Init → платёжная форма → нотификации →
Confirm/Cancel, плюс верификация счетов (AV) и e2c-выплаты.

## 1. Поднять стенд

```bash
docker compose up tbank-mock     # http://localhost:3100
# или без docker: npm run start:tbank
```

Мерчантская часть (ваша интеграция) должна принимать вебхуки. Для локальной
проверки укажите в Init `NotificationURL=http://host.docker.internal:PORT/webhook`
или задайте `MOCK_DEFAULT_NOTIFICATION_URL` на стенде.

## 2. Базовый флоу

```bash
# Init: создать платёжную сессию
curl -s http://localhost:3100/v2/Init -H 'Content-Type: application/json' -d '{
  "TerminalKey": "TBANKMOCKTEST", "OrderId": "order-1", "Amount": 100000,
  "CreateDealWithType": "NN", "NotificationURL": "http://host.docker.internal:8080/webhook",
  "SuccessURL": "https://myapp.test/success/{order_id}", "FailURL": "https://myapp.test/fail/{order_id}"
}'
# → { PaymentURL, PaymentId, Status: "NEW" }
```

Откройте `PaymentURL` в браузере: на форме — тестовые карты со сценариями
(успех/3DS-challenge/недостаточно средств/отказ). Коды 3DS: `1qwezxc`.

3. Подпись. Каждый API-запрос подписывается `Token` = sha256 по алгоритму
«значения top-level скаляров (без Token, null, пустых) + Password, отсортированные
по ключу, boolean в нижнем регистре» — конспект с примерами:
`docs/reference/tbank/02-notifications-signature.md`. Нотификации от мока
подписаны так же; мерчант обязан проверять (мок умеет слать дубли — кнопка
в `/admin`, для проверки идемпотентности).

## 3. Сценарии и консоль

`/admin` — платежи со историей статусов, сделки (баланс), поступления AV,
верификации, нотификации (статус доставки, ретраи, кнопка «повторить»),
кнопки сценариев: «банк подтвердил холд», «отмена платформой», «чарджбэк эмитента».

## 4. Ошибки (DX)

Ошибка — не голый код: `Details` содержит `Field` (какое поле), `Hint`
(рекомендация) и `Doc` (раздел официальной документации). Известные коды:
7 (невалидные параметры), 8 (не найдено), 13 (подпись), 32 (недоступно
в статусе), 501 (метод не реализован в моке).

## 5. Чеклист готовности к бою

- [ ] все нотификации проверяют Token, ответ 200 «OK» ровно на подтверждённые
- [ ] дубли и ретраи нотификаций обрабатываются идемпотентно (кнопка «повторить»/«дубль»)
- [ ] переходы Confirm/Cancel только из допустимых статусов (см. историю в /admin)
- [ ] чарджбэк-сценарий доводит вашу логику до корректного финала
- [ ] смена `TBANK_API_URL` на боевой хост + реальные TerminalKey/Password —
      код интеграции не меняется
