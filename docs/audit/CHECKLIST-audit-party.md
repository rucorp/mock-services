# Чек-лист аудит-партии (read-only)

> Как провести одну партию глубокого аудита из [`AUDIT-PREP-2026-10-12.md`](AUDIT-PREP-2026-10-12.md) §4.
> Режим партии: **только чтение.** Код, тесты, compose и CI не меняются; единственный
> добавляемый файл — отчёт `docs/audit/AUDIT-PARTY-<id>-<ГГГГ-ММ-ДД>.md`.
> Правила для агентов — [`AGENTS.md`](../../AGENTS.md).

## 0. Подготовка (30 минут)

- [ ] Зафиксировать базу: `git rev-parse --short HEAD`, `node -p "require('./package.json').version"`, `git status` (чисто).
- [ ] Прочитать рамки партии в [`AUDIT-PREP-2026-10-12.md`](AUDIT-PREP-2026-10-12.md) §4: **область** (файлы + диапазоны строк), **вопросы**, **критерии приёмки**.
- [ ] Записать базовый прогон: `npm test` (полный вывод финальных строк: core, 4 selftest'а, upstream, links, drift). Зелёная база обязательна; красный старт — блок и вопрос координатору, а не «починю по ходу».
- [ ] Открыть источник истины по протоколу: `protocols/<provider>.json`, `docs/reference/<provider>/**`, `docs/integration/<provider>.md`. Для вопросов безопасности — [`SECURITY.md`](../../SECURITY.md) + [`docs/rfc/RFC-001-multi-tenant-sandboxes.md`](../rfc/RFC-001-multi-tenant-sandboxes.md).
- [ ] Создать ветку `arena/<срез>-audit-<id>`; **не** трогать `main`.

## 1. Область → критерии

- [ ] В шапке отчёта: issue-партии, база (коммит), **список файлов с диапазонами строк** и явное перечисление того, что осталось за рамками.
- [ ] По каждому файлу — отметка «прочитан полностью, строки в scope не пропускались» (как §3 реестра [`REGISTRY-2026-10-11-code-sweep.md`](REGISTRY-2026-10-11-code-sweep.md)) или честное «проверено 1–N».
- [ ] Каждый `[VERIFY]` из брифа, попавший в область, закрыт **двумя** способами: цитата кода `файл:строка` **и** воспроизведение (команда + вывод). Только чтение кода — не доказательство для security-утверждений.
- [ ] Критерии приёмки партии превращены в чек-бокс-список в отчёте; невыполненный пункт остаётся незакрытым (без «в целом похоже»).

## 2. Как искать (приёмы, применимые в этом репо)

- [ ] Прогнать ядро точечно: `node -e "const c=require('./packages/core'); …"` — проверка классификаторов (`isPrivateAddress`, `classifyKey`, `parseDuration`, `resolveTenancyMode`, `generateSandboxId`).
- [ ] Проверить нормализацию входных данных **парсером, а не человеком**: что отдаёт `new URL(x).hostname`/`searchParams` для вашего пэйлоада.
- [ ] Для сетевой границы — поднять listener на `127.0.0.1:0` в песочнице и проверить, доходит ли запрос (фиксировать и «гард пропустил», и «соединение всё равно не установлено»: это разные severity).
- [ ] Для «реализовано ли» — не доверять `grep`: маршрут может упоминаться только в комментарии (именно так устроен `check:drift`, см. [`scripts/check-protocol-drift.js:60-62`](../../scripts/check-protocol-drift.js)).
- [ ] Сверить «обещано в доке ↔ есть в коде ↔ есть тест»: три колонки для каждого env и для каждого защищённого маршрута.
- [ ] Проверить границы числа/размера (0, `''`, `-1`, `NaN`, `Infinity`, 5 МБ+1, многобайтовый UTF-8) и поведение после отказа (дренирование, `done`-флаги, повторная отправка).
- [ ] Проверить изоляцию: параллельные запросы с разными `X-Mock-Sandbox`, доступ без токена, `/sandboxes/me`, экспорт/импорт чужой песочницы, `?sandbox=` и поддомен.
- [ ] Проверить «нет ли лишней поверхности»: какие маршруты не требуют `MOCK_OPERATOR_TOKEN`/`MOCK_ADMIN_TOKEN`, что отдают `/mock/*` при `MOCK_HOSTED=1`, что попадает в `MOCK_STATE_FILE`.
- [ ] Юридический блок (если партия его касается): поиск сторонних копий (`*.html`, дословные абзацы), упоминаний внутренних клиентов/контактов, дефолтных реквизитов.

## 3. Формат находки

Каждая находка — одна строка реестра + (при необходимости) блок воспроизведения.

```
| ID | модуль | файл:строка | категория | severity | суть | предлагаемая задача | зависимости |
```

* **ID:** `P<партия>-<NN>` (например `PA-03`), чтобы не смешивать с `F-…` (#15) и `A-…` (аудит 08.10) и `MS-…` (бриф).
* **категория:** `security` / `protocol` / `correctness` / `resilience` / `dx` / `legal` / `docs`.
* **severity:** `blocker` (блокирует публикацию или публичный стенд) / `major` / `minor` / `info`.
* **суть:** фактическое поведение + чем подтверждено; без предложений «на пару абзацев».
* **предлагаемая задача:** один абзац — что сделать и критерий готовности; **не** код.
* Блок воспроизведения: команда → вывод → вывод одной строкой. Если не воспроизводится —
  находка помечается `[не подтверждено]` и уходит в вопросы, а не в реестр.
* Если находка дублирует MS-/F-/A- — так и писать («дубль MS-09», «уточняет MS-16»), новый
  ID не заводить.

## 5. Запреты партии

* Правки кода, тестов, compose, CI, манифестов — под любым предлогом («мелкий фикс попутно»).
* Изменение `[DECISION]`-пунктов и приоритетов P0/P1/P2 единолично: только предложение владельцу.
* Ослабление или удаление теста ради зелёного прогона; добавление зависимости; реальный PAN/ПДн/секреты в примерах.
* Формулировки «вроде бы», «вероятно, закрыто» без строки-доказательства; утверждения о состоянии GHCR/истории git без прогона (в песочнице они непроверяемы — так и писать).
