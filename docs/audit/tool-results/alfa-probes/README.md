# SZ probe-скрипты аудита alfa-mock — воспроизводимые доказательства к AUDIT-SZ-ALFA-2026-10-12

Скрипты — живые пробы независимого SZ-аудита альфы (серия PG-01…PG-11) и аддендума post-#55.
Запуск: `node docs/audit/tool-results/alfa-probes/<скрипт>.js` из корня репо (пути резолвятся от `__dirname`,
CWD не важен). Требования: Node >= 20; внешняя сеть не нужна. Безопасность: все listener'ы только
`127.0.0.1:0`, исходящие доставки — только на локальные фикстуры; `alfa-dns-toctou.js` подменяет DNS
исключительно внутри собственного процесса. Код репозитория скрипты не изменяют.

Адаптация харнесса (причина замечаний к P5/P6 в сигнале #62 — гонка capture стартового лога, не /health):
- `startAlfa` снимал слушатели вывода при первом чанке с портом; boot-блок (creds/callbacks/control-plane) печатается
  следующими console.error-чанками и терялся → P1-лог/P5/P6 слепли (retry=undefined, session_timeout=undefined,
  guardOn=false). Слушатели больше не снимаются, резолв с задержкой 300мс. `/health` guardOn не содержал ни на одной
  ревизии — проба читает стартовый лог.
- P5: вердикт-логика приведена к предрегистрации PG-05 ≡ PB-11 — «дефект подтверждён» = '1h' тихо → 1000мс
  (parseInt('1h')=1 → Math.max(1000,1)), '0' тихо → 1200, WARN нет; прежний внутренний эталон '10000' не соответствовал
  дефекту. На f6e7cf3e дефект воспроизводится — PG-05 в силе (#58). После #58 ожидание инвертируется (WARN или честный парс).
- P6 после адаптации: block_private_webhooks=true (стартовый лог), доставок на приватный приёмник 0 (прямой и
  mapped-IPv6) — гард активен, регресс не маскируется; PF-01 в альфе по-прежнему не растиражирован.
- Контроль «до» (e133a6b, адаптированный бандл): P2a/b/c воспроизводят PA-50, остальные вердикты без изменений.

(хеш даёт координатор), а не при осмотре диффа. Регресс-контур: `npm test` (core 48 · tbank PASSED ·
kassa 141 · yookassa 227 · atol 202 · alfa 287 · upstream 11) + `check:links` (71 файл на `6d13b81`) +
